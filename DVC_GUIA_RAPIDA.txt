================================================================================
GUIA RAPIDA DE USO: DVC + GIT + GOOGLE DRIVE + DOCKER (spc_project)
================================================================================

1. ¿COMO FUNCIONA ESTE PROYECTO?
--------------------------------------------------------------------------------
- GIT (GitHub): Guarda el codigo, scripts, params.yaml, dvc.yaml, dvc.lock, metricas
  y los archivos puntero (*.dvc).
- DVC (Google Drive): Guarda los datos reales pesados (data/raw/, data/interim/,
  data/processed/) y los artefactos de modelos (models/*.pkl).
- DOCKER: Entorno autocontenido para ejecutar el pipeline de ML y levantar MLflow UI.


================================================================================
2. PASO PREVIO: OBTENER LOS DATOS EN TU MAQUINA (HOST)
================================================================================

Antes de ejecutar Docker o el pipeline local, debes tener el dataset data/raw/salary.csv.

A) SI YA TIENES DVC INSTALADO:
   dvc pull

   (En Windows con el entorno del proyecto: .\.venv-dvc\Scripts\dvc.exe pull)

B) SI NO TIENES DVC INSTALADO:
   1. Instala DVC y el plugin de Google Drive:
      pip install dvc dvc-gdrive

   2. Descarga los datos:
      dvc pull

   *Nota:* DVC abrira tu navegador web la primera vez para autenticarte con Google Drive.

C) METODO MANUAL ALTERNATIVO:
   Coloca el archivo 'salary.csv' directamente en 'data/raw/salary.csv'.


================================================================================
3. EJECUTAR CON DOCKER (1 SOLO COMANDO)
================================================================================

Una vez tengas data/raw/salary.csv:

   docker compose up

- Esto ejecutara el pipeline completo y levantara MLflow en:
  http://localhost:8080


================================================================================
4. COMANDOS DEL DIA A DIA CON DVC (DESARROLLO LOCAL)
================================================================================

A) MODIFICAR HIPERPARAMETROS
   - Edita el archivo `params.yaml` (ej: n_estimators, max_depth, test_size, etc.).

B) REPRODUCIR EL PIPELINE COMPLETO
   dvc repro
   (DVC detecta automaticamente que cambio y re-ejecuta solo las etapas afectadas).

C) VER LAS METRICAS OBTENIDAS
   dvc metrics show

D) COMPARAR METRICAS Y PARAMETROS CON EL EXPERIMENTO ANTERIOR
   dvc params diff
   dvc metrics diff

E) GUARDAR EL EXPERIMENTO EN GIT (GITHUB)
   git add dvc.yaml dvc.lock params.yaml spc_module/ reports/
   git commit -m "experiment: cambio de hiperparametros en params.yaml"
   git push

F) SUBIR LOS NUEVOS DATOS/MODELOS A GOOGLE DRIVE
   dvc push


================================================================================
5. ESTRUCTURA DE ARCHIVOS CLAVE
================================================================================
- params.yaml          -> Panel central de parametros del modelo y dataset.
- dvc.yaml             -> Definicion de etapas del pipeline (prepare, featurize, train).
- dvc.lock             -> Registro del estado y hashes de la ultima ejecucion de dvc repro.
- reports/metrics.json -> Metricas registradas (Accuracy, Precision, Recall, F1).
- data/raw/salary.csv.dvc -> Puntero que vincula salary.csv con Google Drive.
- .dvc/config          -> Configuracion del remote de Google Drive.
- Dockerfile           -> Imagen Docker con todas las dependencias.
- compose.yaml         -> Orquestacion del contenedor y mapeo de puertos/volumenes.
- docker-entrypoint.sh -> Script de arranque del contenedor (valida datos y corre pipeline).
